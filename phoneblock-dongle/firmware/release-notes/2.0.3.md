# PhoneBlock Dongle 2.0.3

*unreleased*

- Status emails with a longer call list could be rejected by some mail
  servers: The call table was sent as one line longer than SMTP allows.
  It is now split into short lines. Failed SMTP commands are now logged
  with the step and, if the server answered, its reply code.
- Wi-Fi transmit power defaults to 15 dBm and can be adjusted from 8 to
  20 dBm in the web UI. Changes take effect immediately.
- **Display on the LilyGO T-Display V1.1 (#708).** The classic ESP32
  firmware drives the board's 240x135 screen (logo, spam badge, caller).
  Select the board under System ▸ Board; the display is off by default.
  Not available on the ESP32-PICO-D4 dongle, whose flash uses a display pin.
- After a call, the caller stays on the display (T-Dongle-S3 and
  T-Display) until it dims a minute later, so short calls can still be read.
- A call arriving while the dongle renewed its SIP registration could make
  the renewal fail ("REGISTER rejected: -1"). The registration now waits for
  the answer to its own request, handles the call normally, and no longer
  warns about a duplicate "200 OK" from the Fritz!Box (#771).
- Built with ESP-IDF v5.5.6 instead of v5.3 (#350): two years of Espressif
  Wi-Fi fixes. Aimed at the occasional restart of 2.0.2 dongles after days
  of uptime, where received Wi-Fi data had overwritten memory.
- The web UI could show raw text keys instead of labels when the dongle
  did not answer a request while the page loaded. It now reloads the
  strings with the next status update instead of only on F5 (#770).
- Less memory needed by the web UI's log display: the log is sent entry by
  entry instead of as one 9 KB block, which failed with "500 out of memory"
  on dongles short of memory. A clip set that could not be read for lack of
  memory is no longer reported as "malformed clip table" (#770).
- With access protection on, login could loop back to the login page when
  the browser also held cookies of another service on the same IP (e.g. a
  NAS web UI next to the Docker container): the cookie header was clipped
  at 256 bytes and the session cookie lost.
- The email, SIP and setup password fields now tell the browser not to
  fill in saved passwords. A password filled in by the browser could
  replace the stored SMTP password and make every status email fail with
  "535" (#792).
