# PhoneBlock Dongle 1.7.0

*unreleased*

## Added

- **Act on calls straight from the call list.** "⚠ Spam" reports a call that
  got through to PhoneBlock; the number is blocked from the next call on.
  "＋ Kontakt" writes an unnamed caller into a Fritz!Box phonebook — for a
  blocked caller this also puts the number on your whitelist. Without a
  Fritz!Box, "✓ Whitelist" unblocks a wrongly blocked number. Each row shows
  the caller's current state, and offers only the actions that change it.

- A number on your own whitelist is no longer blocked by a caller-name
  pattern, and calls blocked by a pattern are reported to PhoneBlock like
  other blocked spam calls.

- **Choose which phonebook new contacts go to.** Asked once, changeable under
  "Telefonbuch für neue Kontakte". Phonebooks that synchronise with an online
  address book (CardDAV, Google) are shown but cannot be selected: the
  Fritz!Box rejects writes to them. Needs a dongle set up with the Fritz!Box
  wizard.

- **ESP32-C3 boards (e.g. "C3 Super Mini").** The firmware now also ships for
  the ESP32-C3, installable from the browser and updated over the air like the
  ESP32 dongle.

- **LilyGO T-Dongle-S3 (ESP32-S3).** A ready-made stick with a USB-A plug
  that goes straight into the Fritz!Box — no soldering, no adapter.
  Installable from the browser and updated over the air; the RGB LED shows
  the status (#602), the display shows the PhoneBlock logo (#606) and can
  be turned upside down under "System" (#608). Its whole free flash
  (~9.6 MB) is storage, enough for the full dialog set (#674).

- **T-Dongle-S3 display shows the caller (#628).** During a call: the name
  from the Fritz!Box phonebook above the number, or the number with its
  PhoneBlock rating (red SPAM, orange suspected, with the vote count). At
  rest, a red badge on the logo counts the blocked spam calls in the call
  list; clearing the list clears it.

- **Linux version as a Docker image.** The Linux version (next item) is also
  on Docker Hub as `phoneblock/answerbot2` (amd64, arm64, armhf), built from
  the same package with every release. It replaces the old AnswerBot container
  (`phoneblock/answerbot`); see `phoneblock-dongle/debian/README.md`.

- **Linux version (#631).** The dongle firmware also runs as a service on a
  Raspberry Pi or another Debian/Ubuntu machine in the home network, with the
  same web UI and version as the dongle. Install and update it with `apt`
  from https://haumacher.github.io/phoneblock/apt/.

- **Call time in `/api/calls` (#644).** Each call now carries its absolute
  time (`epoch_s`, UTC seconds since 1970) next to its age, so Home
  Assistant, ioBroker or Node-RED can read the call list without working
  it out themselves. 0 while the dongle's clock is not set yet. Spam calls
  also carry how long the dongle had them on the line (`duration_s`), which
  shows callers who hang up before the announcement ends.

- **Call webhook (#644).** Under "Webhook bei Anrufen" the dongle can post
  every call in the call list to an address in your home network, e.g. a
  Home Assistant, ioBroker or Node-RED webhook, so they learn about calls
  without polling. Plain http only; the body is the call as `/api/calls`
  lists it. A spam call is posted when it ends, with its duration.

- **Chip temperature on the System card** for boards whose chip has a
  sensor (ESP32-C3); the classic ESP32 dongle has none.

- **Device type with your API keys (#640).** The dongle reports its chip
  (ESP32, ESP32-C3, ESP32-S3) and the Linux version "Linux" in its
  User-Agent, so the API key list in your PhoneBlock settings shows which
  device uses which key.

- **Talking to spam callers (#429).** Under "Spam-Ansage" the dongle can,
  instead of playing the announcement and hanging up, hold a conversation:
  it listens to the caller and answers with short sentences for as long as
  they stay on the line. New installations start with it; an updated
  dongle keeps its announcement until you switch. The sentences (14
  languages; the more storage the dongle has, the more of them) are
  downloaded in this mode and replace the announcement — an own recording
  is deleted on the switch. Silence threshold, response time and line noise
  are adjustable.

- **Announcements and sentences update without a firmware update.** The
  dongle checks for new audio once a day.

- **PhoneBlock sign-in through Home Assistant (#621).** Opened through Home
  Assistant ingress, the Linux version links the PhoneBlock account with a
  code: "PhoneBlock-Account verknüpfen" opens phoneblock.net, you confirm the
  code shown there, and the service fetches the key itself. Everywhere else
  the sign-in is unchanged.

## Changed

- **ESP32 dongles reformat their storage on the update (LittleFS, as on the
  ESP32-C3).** Blocklists, announcements and language packs are downloaded
  again by themselves; settings are kept. **An own recorded announcement is
  lost and must be uploaded again.** In return the ESP32 has room for as many
  dialog sentences as the ESP32-C3.

- The web page no longer polls the dongle while its browser tab is in the
  background and refreshes as soon as it is shown again — an open background
  tab caused about one request (and DNS lookup, e.g. in a Pi-hole) per
  second (#573).

## Fixed

- A failed connection test now names the address it tried, and a server
  error page shows up in the log by its title instead of as raw HTML (#532).

- A firmware without published language packs (e.g. a development build) no
  longer asks the CDN for them every 5 minutes: it says so once in the log
  and keeps the English texts (#673).

- When sending call audio fails, the log now shows the free memory, so a
  memory shortage can be told from a congested Wi-Fi (#531).

- Linking the PhoneBlock account opens phoneblock.net in its own tab, which
  closes itself once the token is stored; the dongle page stays open and
  shows the result (#619).

- Many requests in a row (e.g. the first call-barring sync with many
  numbers) no longer run the dongle out of memory: closed connections now
  release their memory after 2 seconds instead of 2 minutes (#601).

- Saving a setting unrelated to SIP (LED, display, mail, …) no longer
  re-registers the dongle with the Fritz!Box (#611).

- If "Zugriff für Apps" (TR-064) is switched off on the Fritz!Box, the setup
  wizard now says so and names the setting, instead of asking for the
  Fritz!Box username (#651).

- About 8 KB more free memory in normal operation: Wi-Fi setup from the
  browser installer (USB) is available for 10 minutes after plugging in,
  then the service ends if the dongle is online (#599).

- A firmware or announcement upload no longer aborts on a short stall in
  the transfer; if it does fail, the log now says why (#597).

- Test calls (e.g. **622) are listed as "Test" and no longer counted as
  spam; anonymous and internal calls show "unbekannt" instead of "legitim".

- A rating comment containing a quotation mark would have produced a malformed
  request. Comments are now escaped correctly.

- If downloading the announcement fails after a restart, the dongle retries
  within minutes instead of a day later. A spam call answered without an
  announcement now leaves a warning in the log.

- The storage no longer fills up with the warning "SPIFFS_gc failed" while
  plenty of space is shown free (#529, #530, #542). The announcement, mail
  texts and your own recording now come first; the community blocklist kept on
  the dongle takes only the space that remains. While your own recording is
  active, the localized announcement is not stored.
